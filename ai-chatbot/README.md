# AI Chatbot Folder Explained

This folder is the Python backend for the AI chat feature. It is a FastAPI application that receives chat requests, validates the user via JWT, loads the conversation history from MongoDB, sends the conversation to a Gemini model, stores the result, and returns the AI response back to the frontend through the Express gateway.

## 1. Overall purpose of the folder

The `ai-chatbot` folder is not a standalone app in the sense of a full website. It is the AI service layer of the MERN stack.

Its responsibilities are:

- Accept chat requests from the Node/Express server
- Validate JWT tokens
- Read or create chat conversations
- Save user and AI messages in MongoDB
- Call the Gemini AI model for responses
- Return structured JSON to the frontend or gateway

In short:

- `server/` handles authentication and web app hosting
- `ai-chatbot/` handles the AI chat logic and messages

## 3. Terminology used in this project

### FastAPI
FastAPI is a Python web framework used to build APIs quickly. It automatically validates request bodies using Python models and returns JSON responses.

### APIRouter
`APIRouter` is used to organize routes in separate files. Instead of putting all routes in one file, the app groups the chat endpoints in `routes/chat.py` and includes them in `main.py`.

### Pydantic model
Pydantic models are Python classes that define the expected structure of incoming or outgoing API data.

Examples from `routes/chat.py`:

- `Message` → represents one message object with `role` and `content`
- `ChatRequest` → request body sent when user sends a message
- `ChatResponse` → response returned after AI answer is generated
- `ConversationResponse` → response format for a conversation summary

These models help keep data consistent and validated.

### JWT (JSON Web Token)
JWT is a signed token sent in the Authorization header. It identifies the user. The backend verifies it before processing chat requests.

### MongoDB
MongoDB is the database used to store chat conversations and messages. The project uses two collections:

- `conversations`
- `messages`

### Gemini API
The AI is connected through Google’s `google-generativeai` SDK. The model used in the code is:

- `gemini-3.6-flash`

Even though older setup docs may mention OpenAI, the actual Python service here is using Gemini.

### conversation_id
This is the unique ID of a chat thread. It ties all messages together for one conversation.

### tokens_used
This is how many tokens the model consumed while generating the response. It is returned from the AI API and saved in the message record.

### role
Message role is usually:

- `user` → message sent by user
- `assistant` → message generated by AI

## 4. File-by-file explanation

## `main.py`

This is the main runtime file.

### What it does

```python
app = FastAPI(...)
```
This creates the FastAPI application object.

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)
```
This enables CORS so the frontend or gateway can call the API from another port/domain.

```python
JWT_SECRET = os.getenv("JWT_SECRET", "your_jwt_secret")
```
This reads the JWT secret from the `.env` file so the backend can verify the same token created by the Express app.

```python
def verify_token(authorization: str = None):
```
This function checks the Authorization header, extracts the token, decodes it using JWT, and raises a 401 or 403 if invalid.

```python
app.include_router(chat_router, prefix="/chat")
```
This plugs in the chat routes under the `/chat` prefix. So the actual endpoints become:

- `/chat/message`
- `/chat/conversations`
- `/chat/history/{conversation_id}`
- `/chat/conversation/{conversation_id}`
- `/chat/new-conversation`

```python

```
This returns a basic status to confirm the API is up.

```python
if __name__ == "__main__":
    uvicorn.run(app, host="0.0.0.0", port=8000)
```
This starts the FastAPI server on port 8000.

### Return behavior

`verify_token()` returns decoded JWT data if valid, otherwise raises an HTTPException.

`health_check()` returns:

```json

  "status": "healthy",
  "timestamp": "current datetime"
```

## `routes/chat.py`

This file is the core API logic for chat.

### Important objects created at startup

```python
chat_router = APIRouter()
chat_model = ChatModel()
db = ChatHistory()
```

These three objects are central:

- `chat_router` holds all chat routes
- `chat_model` is the AI model wrapper
- `db` is the MongoDB data layer

### Pydantic request/response models

```python
class Message(BaseModel):
    role: str
    content: str
```
Represents one message in chat history.

```python
class ChatRequest(BaseModel):
    message: str
    conversation_id: Optional[str] = None
    temperature: Optional[float] = 0.7
```
This is the payload the client sends to send a question to the AI.

- `message`: the user prompt
- `conversation_id`: optional existing chat ID
- `temperature`: creativity/variation setting for the AI response

```python
class ChatResponse(BaseModel):
    conversation_id: str
    message: str
    timestamp: datetime
    tokens_used: int
    success: bool
```
This is the standardized response returned after a message is processed.

### `verify_token(authorization: str)`

This function validates the incoming JWT just like the one in `main.py` but inside the chat route module. It extracts the bearer token and decodes the payload.

If valid, it returns the decoded user payload (for example, user id). If invalid, it raises an HTTP 403 error.

### `@chat_router.post("/message", response_model=ChatResponse)`

This is the main route for sending a user message.

#### Flow of the function

1. Reads the Authorization header
2. Verifies the JWT token
3. Extracts `user_id`
4. Creates a new conversation if `conversation_id` is missing
5. Fetches previous conversation messages from MongoDB
6. Builds a message list for Gemini:
   - system instruction
   - previous chat history
   - new user message
7. Calls `chat_model.generate_response(...)`
8. Saves the new user message and AI response into MongoDB
9. Returns the AI-generated answer with the conversation id and token count

#### Example logic

```python
messages = [
    {
        "role": "system",
        "content": "You are a helpful AI assistant similar to Gemeni. Provide concise, accurate, and helpful responses."
    }
]
```
This system prompt tells the model how to answer.

Then it appends previous conversation history and the latest user message.

```python
result = chat_model.generate_response(messages, request.temperature)
```
This is the call to the AI model.

If the AI call fails, it raises a 500 error:

```python
if not result["success"]:
    raise HTTPException(status_code=500, detail=result["error"])
```

Then the code saves both messages:

```python
db.add_message(request.conversation_id, "user", request.message)
db.add_message(request.conversation_id, "assistant", result["content"], result["tokens_used"])
```

Finally it returns:

```python
return ChatResponse(
    conversation_id=request.conversation_id,
    message=result["content"],
    timestamp=datetime.now(),
    tokens_used=result["tokens_used"],
    success=True
)
```

### `@chat_router.get("/conversations")`

This fetches all conversations for the logged-in user.

```python
user_data = verify_token(authorization)
user_id = user_data.get("id")
conversations = db.get_user_conversations(user_id)
```
It returns a list of conversation documents sorted by update time.

### `@chat_router.get("/history/{conversation_id}")`

This fetches all messages inside one conversation.

It verifies the JWT, then calls:

```python
messages = db.get_conversation_history(conversation_id)
```
Returns:

```json
{
  "messages": [ ... ]
}
```

### `@chat_router.delete("/conversation/{conversation_id}")`

This deletes one entire conversation and all its messages.

```python
db.delete_conversation(conversation_id)
```
Returns a simple confirmation message.

### `@chat_router.post("/new-conversation")`

This creates a new conversation with a default title, usually `New Chat`.

```python
conversation_id = db.create_conversation(user_id, title)
```
Returns:

```json
{
  "conversation_id": "...",
  "title": "New Chat"
}
```

## `models/chatModel.py`

This file wraps the actual Gemini API call.

### Class: `ChatModel`

```python
class ChatModel:
```
This class is responsible for interacting with the AI model.

### `__init__()`

```python
self.api_key = os.getenv("GEMINI_API_KEY")
```
Loads the API key from environment variables.

```python
if not self.api_key:
    raise ValueError("GEMINI_API_KEY not set in environment")
```
If the key is missing, the app fails early with a clear error.

```python
genai.configure(api_key=self.api_key)
self.model_name = "gemini-3.6-flash"
self.model = genai.GenerativeModel(self.model_name)
```
This creates the configured Gemini model object.

### `generate_response(messages, temperature=0.7)`

This is the main method that generates the model answer.

#### What it does

1. Takes a list of previous message dictionaries
2. Converts them into a single prompt string
3. Calls `self.model.generate_content(...)`
4. Extracts the response text
5. Returns metadata like token usage and success status

```python
prompt = "\n".join(f"{m['role']}: {m['content']}" for m in messages if m.get('content'))
```
This joins the conversation into one text prompt that the AI understands.

```python
response = self.model.generate_content(
    prompt,
    generation_config={
        "temperature": temperature,
        "max_output_tokens": 2000,
    },
)
```
This sends the prompt to Gemini with:

- `temperature`: controls creativity
- `max_output_tokens`: maximum output limit

Then it tries to read the answer:

```python
content = response.text if hasattr(response, "text") else ""
```
If successful, it returns:

```python
{
    "content": content,
    "tokens_used": ...,
    "model": self.model_name,
    "success": True,
}
```

If anything fails, it returns:

```python
{
    "content": None,
    "error": str(e),
    "success": False,
}
```

This is important because the route file checks:

```python
if not result["success"]:
```
and handles errors gracefully.

### `set_model(model_name)`

This allows switching to another Gemini model if needed.

## `database/chatHistory.py`

This file is the MongoDB layer. It is responsible for managing all conversation and message data.

### Class: `ChatHistory`

```python
class ChatHistory:
```
This class manages the database connection and operations.

### `__init__()`

```python
mongodb_uri = os.getenv("MONGODB_URI", "mongodb://localhost:27017/chatbot")
database_name = os.getenv("MONGODB_DB", "chatmessage")
```
These variables read the database URL and database name from `.env`.

```python
self.client = MongoClient(mongodb_uri, serverSelectionTimeoutMS=20000)
self.db = self.client[database_name]
self.conversations = self.db["conversations"]
self.messages = self.db["messages"]
```
This creates connections to MongoDB and selects the collections used by the chatbot.

### `_convert_id(doc)`
This helper converts MongoDB ObjectId values to strings so they can be returned easily via JSON.

### `create_conversation(user_id, title="New Chat")`

This creates a new conversation record.

Example inserted document:

```python
{
    "user_id": user_id,
    "title": title,
    "created_at": datetime.now(),
    "updated_at": datetime.now(),
    "message_count": 0
}
```

It returns the inserted conversation ID as a string.

### `add_message(conversation_id, role, content, tokens_used=0)`

This writes a message into the `messages` collection.

Example document:

```python
{
    "conversation_id": conversation_id,
    "role": "user",
    "content": "Hello",
    "timestamp": datetime.now(),
    "tokens_used": 120
}
```

It also updates the conversation row by:

- setting `updated_at` to now
- incrementing `message_count` by 1

### `get_conversation_history(conversation_id)`

This fetches all messages in one conversation ordered by timestamp ascending.

It returns a list of message dictionaries with `_id` converted to string.

### `get_user_conversations(user_id)`

This fetches all conversations for a user ordered by newest updated conversations first.

It returns:

```python
[
    {
        "_id": "...",
        "user_id": "...",
        "title": "...",
        "created_at": ...,
        "updated_at": ...,
        "message_count": ...
    }
]
```

### `delete_conversation(conversation_id)`

This deletes:

1. all messages in that conversation
2. the conversation document itself

This ensures chat data is fully removed when a user deletes a chat thread.

## 5. How the request flow works

The high-level flow is:

```text
Frontend / Express
    ↓
POST /api/chat/message
    ↓
Express proxy forwards to FastAPI
    ↓
FastAPI verifies JWT
    ↓
MongoDB pulls previous conversation
    ↓
Gemini generates response
    ↓
MongoDB saves user + assistant message
    ↓
FastAPI returns response JSON
    ↓
Express forwards response to frontend
```

### Example

A user sends the message: "Explain recursion in Python"

1. `routes/chat.py` validates Authorization
2. `db.get_conversation_history(conversation_id)` gets previous messages
3. `ChatModel.generate_response(...)` sends the entire conversation to Gemini
4. The AI response is returned
5. `db.add_message(...)` saves the JSON in MongoDB
6. The route returns a response like:

```json
{
  "conversation_id": "66f0c9...",
  "message": "Recursion is when a function calls itself...",
  "timestamp": "2026-09-01T12:00:00",
  "tokens_used": 210,
  "success": true
}
```

## 7. Important coding patterns used in this project

### Dependency injection style
The app stores service objects once:

```python
chat_model = ChatModel()
db = ChatHistory()
```
This makes the route code cleaner and avoids recreating DB or AI connections on every request.

### Use of response models
`response_model=ChatResponse` makes FastAPI automatically serialize the output in a consistent JSON structure.

### Error handling
The project uses `HTTPException` when auth fails or the AI request fails.

### Database + AI + API separation
This is a clean layered design:

- `database/` = data persistence
- `models/` = AI integration
- `routes/` = API requests and business flow
- `main.py` = app bootstrap

That separation makes the system easier to scale and maintain.

## 9. Common things to remember

- The project is a Python-only AI API service, not the full frontend.
- It expects JWT from the Node server, so both sides must share the same secret.
- It uses MongoDB to persist conversations.
- It uses Gemini, not OpenAI, in the current codebase.
- The route file is the orchestration layer: it decides the flow between auth, DB, and AI.
